# 黑屏告警 — 帮助文档

## 这是什么

黑屏告警通过 USB 相机实时监测车机屏幕（或回放问题单视频），自动检测黑屏异常并推送告警卡片到飞书群。检测算法基于屏幕 ROI 标定、列/行暗度剖面和边缘密度规则，可区分"黑屏"与"暗色正常画面"。

## 告警长什么样

红色卡片「🚨 Display Black Screen Detected」，包含：

| 字段 | 含义 |
|---|---|
| 事件 | 事件类型和事件 ID（对应本地证据目录名） |
| 来源 | 相机编号或视频文件名 |
| 视频位置 | 异常在视频中的起始时间（相机模式为 -） |
| 检测时间 | 真实墙钟时间（首帧证据时刻） |
| 帧序号 / 置信分数 / 检出区域 | 定位与复核依据 |
| 证据拼图 | 10 帧合并的现场截图，每帧带时间戳和红框 |
| 证据路径 | 本地完整证据目录 |

一次黑屏只发一条：连续检出攒满 10 帧证据合并发送；黑屏提前恢复时 ≥3 帧也会发送；事件后 10 秒冷却。

## 快速开始

### 1. 群里添加自定义机器人（接收告警）

目标群 → 设置 → 群机器人 → 添加机器人 → 自定义机器人 → 复制 Webhook 地址。

### 2. 配置环境变量

编辑 `Camera-Algorithm\set_feishu_env.ps1`：

```powershell
$env:FEISHU_WEBHOOK = "<自定义机器人 webhook>"
$env:FEISHU_APP_ID = "cli_xxx"        # 本应用凭证，用于卡片内嵌截图
$env:FEISHU_APP_SECRET = "xxx"
# 机器人开启签名校验时再加:
# $env:FEISHU_WEBHOOK_SECRET = "<签名密钥>"
```

App ID / Secret 在 开放平台 → 本应用 → 凭证与基础信息。应用需开通 `im:resource`（上传图片）权限并发布版本。

### 3. 运行

```powershell
cd D:\Dev_Stability\Camera-Algorithm
. .\set_feishu_env.ps1

py -3.12 notify\feishu_notifier.py --test          # 连通性自测
py -3.12 camera_diag.py --detect --notify          # 相机实时监测
py -3.12 camera_diag.py --video 问题单.mp4 --detect --notify   # 视频回放
py -3.12 camera_diag.py --batch data_source --notify           # 批量检测
```

相机模式建议：预览滑条把 AutoExp 调 0（手动曝光）、Gain 调低；按 `C` 标定屏幕 ROI（橙框圈住屏幕），把打印的坐标固定到 `--roi x,y,w,h`。

### 快捷键

`Q` 退出 · `SPACE` 暂停 · `./,` 单帧进退 · `D` 检测开关 · `R` 框选 ROI · `C` 自动标定 · `X` 清除 ROI · `S` 截图

## 常见问题

**收不到任何消息**：先跑 `notify\feishu_notifier.py --test`。报"环境变量未设置"→ 在启动检测的同一个终端先执行 `. .\set_feishu_env.ps1`（或 `setx` 持久化后重开终端）。

**报 key words not found**：机器人安全设置勾了"自定义关键词"，删除关键词或将关键词设为 `Black Screen`。

**报签名/sign 错误**：机器人开了签名校验，补设 `FEISHU_WEBHOOK_SECRET`。

**卡片没有图片，只有路径**：未配置 `FEISHU_APP_ID/SECRET`，或应用未开通 `im:resource` 权限，或修改权限后忘记发布新版本。控制台会打印"截图上传失败"的具体原因；告警本身不受影响。

**误报暗色画面**：确认已固定屏幕 ROI 和手动曝光；仍误报时把事件拼图发给算法维护者，按 TP/FP 复核流程调阈值（见 `skills-anomaly-iteration.md`）。

**相机打开是黑的**：`py -3.12 camera_diag.py` 不带参数运行完整诊断（遍历 backend/fourcc/分辨率），并检查 Windows 隐私设置-相机权限。
